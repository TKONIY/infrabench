Dynamic context parallelism: per-sample CP size and the balanced packing scheduler

Megatron-LMParallelism

Dynamic context parallelism already exists in the tree, but the number of ranks a packed sub-sample is spread over is still taken from one globally configured `cp_size`. This change makes that number per sample, computed from the sample's own length against a per-rank sequence-length budget, and makes the packing scheduler balance on an estimate of each sample's work rather than on its raw length. On top of that it folds dynamic CP into the ordinary packed-sequence path: the batch-fetch call learns a dynamic-CP mode in which each CP group gets its own packing metadata (rather than one packing shared by every rank), each micro-batch carries the CP degree it is actually running at, and a new scheduler redistributes the packed sub-samples across the DP×CP ranks. The separate dynamic-CP forward/backward schedule and the separate dynamic-CP batch slicer are deleted; dynamic CP now rides the packed-sequence machinery.
