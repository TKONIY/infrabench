Refactor emerging optimizer integration

Megatron-LMOptimizer

Make optimizer construction uniform. Today `get_megatron_optimizer` builds Adam and SGD, while Muon is built by its own bespoke function in a Muon-only module. Replace that with a single entry point plus a registry of "emerging" optimizers (Muon, SOAP, …): every optimizer name is resolved the same way, every trainable parameter is routed to the optimizer that should own it, and the resulting per-bucket optimizers are combined into one object the training loop drives.
